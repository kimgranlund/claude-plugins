# Rubric — handoff-block quality (rubric-handoff)

Score a returned handoff block. No canonical rubric for this output lives elsewhere, so it is defined here (authored in the `make-rubric` shape: Dim × Type × 1–5 anchors × a gate rule). Run `scripts/handoff_check.py` first — it settles H1's mechanical half (presence, order, `(none)` markers, the Status enum) deterministically; score the rest by inspection of the block against the work it reports.

| # | Dimension | Type | What it checks | 1 (fail) → 3 (adequate) → 5 (excellent) |
|---|---|---|---|---|
| H1 | Completeness | [gate] | All eight fields present and in order — Status first as a bare `done \| partial \| blocked(reason)` enum, each empty one written `(none)` not omitted (`scripts/handoff_check.py` settles this mechanically — run it first) | 1: fields missing or merged, Status absent (outcome state buried in Summary prose), no way to tell an empty field from a forgotten one · 3: all eight present, Status a valid enum value, empties marked `(none)`, *Files changed* lists every path · 5: + each field tight and on-topic (Summary is outcome, not process; no field padded with another's content; bulky output cited by path, not inlined) |
| H2 | Verifiability | [gate] | A reviewer can confirm the Summary *without re-doing the work*, from **Evidence** + **Tests/checks run** | 1: "tests pass" / "it works" — no command, count, or citation; the reader must re-run or re-read to trust it · 3: gates named by command with their result; key claims carry a `file:line` or a count · 5: + evidence is non-vacuous (a negative control, a count delta, the exact failing→passing transition) and names any gate *not* run, so the true coverage is legible |
| H3 | Honesty of Risks | [review] | Risks name real fragility, assumptions, and blast radius — not reassurance | 1: "no risks" on non-trivial work; known edges or untested combinations hidden · 3: the genuine risks and assumptions listed with their blast radius · 5: + each risk is actionable (what would confirm or fix it), carries its suspected locus (`execution \| spec \| plan`) so the repair can be aimed, and deferred tensions are booked, not buried |
| H4 | Routing-readiness | [review] | **Recommended next action** is a single step with an owner; **Open questions** are real, decision-shaped forks | 1: "various follow-ups remain" / no owner; open questions rhetorical or already answered · 3: one concrete next step + its owner; open questions each need a real decision by a named role/human · 5: + the recommendation reflects the true critical path, and each open question is framed so the decider can answer it in one pass |
| H5 | Freshness | [review] | Composed after draining the inbox (messaging teams; a sealed subagent is graded against the inputs it was dispatched with) — no stale re-ask, re-edit, or retraction | 1: re-asks an answered question, re-edits a committed artifact, or retracts an already-fixed finding · 3: consistent with all delivered messages and the committed tree at hand-back time · 5: + explicitly reconciles any crossed/late message it superseded |

**Gate to promote: H1 and H2 must both be ≥ 3.** A block that is incomplete or unverifiable fails regardless of the other dimensions — those two are what the next step routes and grades on. H3–H5 below 3 are findings to fix, not gate failures.
