# Rubric — Skill-Corpus Audit (cross-cutting)

Scores a whole `skills/` corpus on the four cross-cutting properties **no single-skill review can see**: a naming *grammar*, language *potency*, front-matter *as an interface*, and the composition *graph*. Two dimensions are owned here (N, P — genuinely corpus-level); two delegate to the per-skill standard that already owns them (L → ``linguistic-techniques``, F → ``skill-authoring-standards`` D1 + ``team-or-solo-rules`` D2) and are rolled up across the set. Scoring method (1–5, `[gate]`/`[review]`, gate threshold) is summarized at the bottom.

| # | Dimension | Plane | Type | What it checks | 1 → 3 → 5 |
|---|---|---|---|---|---|
| N | Naming-convention strategy | corpus | [gate] shadow · [review] grammar | `corpus_index.py`: no directory shadows a reserved command (gate); one coherent grammar, families internally consistent, each dir predicts its `/command` and reads as a *capability* (not a command or an agent role) | 1: grammars mixed with no rationale / a family inconsistent within itself / a name reads as a command or an agent · 3: one grammar dominates, exceptions defensible · 5: single deliberate grammar, every family consistent, zero shadow, each name predicts its command |
| L | Linguistic-technique alignment | per-skill → rolled up | [review] (per-skill gate = ``linguistic-techniques`` L1/L3/L6) | every body *instantiates* its procedure rather than *describing* it, and holds the potency lint budget | 1: bodies describe the workflow · 3: mixed across the set · 5: every load-bearing line in every skill instantiates, all within budget — scored via `linguistics-reviewer` |
| F | Front-matter strategy | per-skill + pairwise | [gate] trigger present (harness D1) · [review] differentiation | each `description` is capability + a model-evaluable when-to-use in the user's words; **differentiated from every peer** so routing is unambiguous; `name` treated as display-only (matches dir or omitted); no dead fields | 1: a vague or peer-overlapping description / a dead trigger / redundant frontmatter · 3: each precise and self-contained · 5: each precise **and** differentiated from all peers (no routing collision) + zero dead fields — scored via ``skill-authoring-standards`` D1 + ``team-or-solo-rules`` D2 |
| P | Peer leverage (1+1=3) | corpus graph | [gate] no dangling · [review] completeness | `corpus_index.py` graph: no `[[link]]` points at a non-existent skill (gate); every high-value composition is wired — pipeline chains linked end to end, sibling pairs cross-linked, reciprocal where warranted, standing dependencies preloaded via `skills:` rather than left as prose | 1: skills that obviously compose sit unlinked (a pipeline chain, a sibling pair) · 3: the major pairs are wired, gaps remain · 5: the graph is deliberate — reciprocal where warranted, `skills:` where standing, no isolated skill that should compose, zero dangling — related to ``team-or-solo-rules`` D3 |

**Gate to promote (the corpus is production-ready when):** N — no reserved-command shadow; F — every skill's description triggers (harness D1); L — every skill's body clears L1/L3/L6; P — no dangling `[[link]]`. The `[review]` faces (grammar coherence, per-peer differentiation, graph completeness) are the excellence axes above the floor.

**Top failure to look for first:** an empty composition graph (P) — skills that are individually strong but never wired into each other, so the corpus is a *pile* of skills, not a *system* where 1+1=3. The second: two grammars drifting (N) until a name no longer predicts its command.

---

**Scoring method.** `[gate]` = mechanically checkable (counts, presence/absence, the two scripts' violation exits); score by inspection or by the script. `[review]` = judgment; score against the anchors with cited evidence (`skill:line` or the offending edge/description). Scale 1–5 (1 = failure anchor, 3 = adequate, 5 = excellence anchor); do not round everything to 3. A corpus that trips any gate face is not production-ready regardless of the `[review]` scores.
