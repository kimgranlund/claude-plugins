1. **`check-routing` evidence is recent, not fresh** — Phase 0's routing/dependency-closure
   row rests on PR #344/#345 runs, not a re-run this pass. Detection: Wave 1/2 rows A–E touch
   no routing-surface descriptions directly, but Wave 0's split nomination (F) and Wave 3's
   spec growth (G) could shift routing once executed. Fallback: Phase 4's closeout checklist
   requires `/check-routing` clean for every touched plugin before any wave is considered
   closed — this reproves routing at execution rather than trusting the Phase 0 snapshot.
2. **Row G's owner boundary is unresolved** (docs vs. authorkit for the ADR-0011
   naming-convention spec amendment). Detection: Wave 3 stays contested until a human decides
   who claims the ticket. Fallback: Row G is explicitly NO MOVE at plan time — Wave 3 is
   listed last, blocked on nothing structurally, but requires a human owner decision before
   `file-task` can mint it.
3. **A's 5-plugin blast radius risks a version-slot collision** — the footer retirement (Row
   A) touches design/llm/screens/harness/agent-protocols in one wave. Detection: two
   in-flight tickets bumping the same plugin's version concurrently. Fallback: the Wave 1
   note states the serialization rule explicitly; `dispatch-ticket`'s claim step is the
   enforcement point.
4. **D and E are semantic edits riding on a bloat-audit similarity score** — extracting
   near-duplicate prose could silently drop content that looked identical but carried a
   load-bearing distinction. Detection: a fresh-context critic pass finds meaning lost in the
   extraction. Fallback: both Wave 2 seeds are marked semantic — species changes require the
   critic pass before merge, per `plugin-authoring.md`'s semantic-edit invariant; this plan
   never treats D/E as mechanical.
