# check-entry-file — FLOOR audit, 2026-07-29

Scope: whole skill against skill-writing-rules (command species), with focus on the just-added
`--strict` mode, the mechanize-first ordering in Phase 1 item 2, and the pinned eviction dials
in Phase 3's →SKILL row. Cross-checked against entry-file-rules for restatement.

Verdict: one blocking finding (strict mode's target is never verified), three minor, two notes.

## Blocking

**B1 — Strict mode is defined in Phase 1 but never verified in Phase 4.** Phase 1 item 3 sets
the strict success condition: the projected file targets the seed class (~20–40 lines). Phase 4
item 1 verifies only the default-mode criterion — "C1 under threshold or the remaining length
justified line-by-line". A strict run that lands at 150 lines passes every gate in the skill:
C1 warns at 200 lines, so the strict target is checked nowhere after approval. The mode's
defining constraint has no closing check, which means strict is not coherent end-to-end — the
inverted burden of proof applies during classification and then evaporates at verification.
Fix: Phase 4 item 1 (or a strict-specific clause in the Done predicate) must re-state the check
in strict terms — e.g. "in `--strict`, the surviving file is within the seed class or each line
over it carries its KEEP justification in the report."

## Minor

**M1 — Phase 3's eviction-dials parenthetical is a drift pair with entry-file-rules.** The line
"Landing skills take the standards' pinned eviction dials (knowledge species, `user-invocable:
false`)" restates the dial values entry-file-rules owns ("user-invocable: false,
disable-model-invocation: false") — and restates them incompletely, omitting the second dial.
The skill's own line 19 promises "it is not restated here." The pointer form ("the standards'
pinned eviction dials") is sufficient on its own; the parenthetical values will drift if the
standard's dials ever change. Cut the parenthetical or keep only the species name.

**M2 — Phase 1 item 2 partially restates the standard's mechanize-first rule.** "procedural-
and-checkable goes `→HOOK` (or `→SKILL` with the steps landing as a `/make-script` script,
named in the row), and `→SKILL` prose is the fallback, never the default for a checkable line"
is entry-file-rules' "Mechanize-first ordering" bullet compressed, mechanism and all. The
operational delta the skill adds is only "named in the row" — keep that, and point at the
standard for the ordering itself ("classification follows the standards' mechanize-first
ordering; the script lands named in the row"). Lower severity than M1 because the restatement
is attributed and the classifier genuinely needs the ordering at classification time.

**M3 — The ~20–40 line strict target is a numeric anchor for a concept the standard owns.**
Entry-file-rules' shipped-seed section says ~20 lines; the skill mints a 20–40 range and calls
it "the shipped seed's class." The upper bound has no home in the standard — if the seed
changes, the command's range drifts silently, and the command is now the only place the "seed
class" is quantified. Either the range moves into entry-file-rules (next to the seed) and the
skill points at it, or the skill drops the numbers and says "the shipped seed's class (see the
standard's worked example)". The gloss "identity, invariants, commands, pointers" is a
compressed copy of the standard's residency list — same treatment.

## Note

**N1 — No failed-precondition branch for the target path.** Command species: preconditions gate
first and each failed precondition has a named branch. The skill takes `$ARGUMENTS` with a
default but names no branch for a missing or nonexistent file (Phase 1 item 1 would just error
mid-lint). One line suffices: "target missing → report and stop; nothing to audit is a
finding, not a crash." Pre-existing, not introduced by these edits.

**N2 — No `allowed-tools` grant.** The workflow's fixed verbs (the lint Bash call, Grep/Glob
staleness checks) could be pre-approved per the command-species contract. Optional; noting for
completeness.

## What checks out

- Species story is consistent three ways: command content, `disable-model-invocation: true` +
  `user-invocable: true`, imperative-verb name. Description is written as slash-menu
  documentation (no trigger keywords spent), documents both the default and `--strict`
  invocation, and `argument-hint` carries the new flag — the frontmatter edits are coherent.
- Strict mode reads correctly through Phases 2 and 3: the approval gate, migrate-then-cut
  ordering, DEFERRED protection, and Gate E3 are mode-independent and nothing in them assumes
  default mode. The one gap is Phase 4 (B1).
- Item 4's strict clause (KEEP justification in the Destination column) reuses the existing
  table schema instead of adding a column — right-sized.
- Stopping predicate is a checkable world-state with an explicit NOT-done clause; report format
  is defined; gates E1/E3 are placed in the head. Staleness-first with Grep/Glob verification
  operationalizes the standard rather than restating it.
